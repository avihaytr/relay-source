# Security

Relay is an experimental local-network application and has not received an independent security review. Protocol 6 supports first pairing by directly scanned PC QR (256-bit single-use credential, two-minute lifetime) or a six-digit PIN displayed by the PC (same lifetime, five incorrect attempts). PIN pairing provisionally accepts the TLS certificate only to calculate a short verification code from that actual certificate, fresh challenge and phone key; the phone and PC both display the code, and the phone sends no proof unless the user confirms that they match. mDNS certificate fingerprints are never trusted. Pairing requires phone confirmation and explicit PC approval, persists trust, then closes without starting media. Remembered phones sign fresh P-256 challenges bound to the PC identity and requested session. The PC issues a fresh 256-bit ticket, usable once on that same TLS stream within ten seconds. Both apps offer Forget Device and optional approval for every session. Platform capture consent is always required.

Discovery exposes only device/service location and nonsecret capabilities. It is unauthenticated and can be spoofed or flooded; it cannot supply a trusted fingerprint or authorize media. There is no HTTP server or local APK download endpoint. Install only builds you verify separately, such as your own locally built APK transferred over USB. Do not accept a pairing QR from a website, message, or untrusted screen.

Anyone who can photograph a current QR or see a current PIN can attempt pairing. PIN pairing additionally depends on carefully comparing both verification codes; the six-digit code is a short authentication string and has a nonzero false-match probability. Approve only a request just initiated on your phone; names are labels, while cryptographic keys identify remembered devices. The PC private key and public trust records rely on owner-only Linux files; Android signing keys stay in Android Keystore and its no-backup trust records have a Keystore HMAC. Endpoint compromise, privileged trust-store rollback, camera/QR relay attacks and denial of service are not solved here. Forget locally blocks future remembered authentication and disconnects the active session; forget on both devices to erase both records. Key loss/change requires explicit pairing again. The media listener is still single-session and binds all IPv4 interfaces. Broader availability and resource hardening remain outstanding.

Do not commit keystores, private keys, receiver certificates, session links, pairing tokens, screenshots of private screens, or logs containing credentials. Generated keys and build outputs are excluded by `.gitignore`.

Report vulnerabilities privately to the repository owner through GitHub private vulnerability reporting if enabled, or request a private contact channel without disclosing exploit details publicly. Do not use public issues for secrets.
